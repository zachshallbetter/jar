# Hierarchy of Authority

This project strictly adheres to the canonical authority hierarchy:

$$\text{Architecture \& Doctrine} \to \text{Ontology \& Vocabulary} \to \text{Formal Specification} \to \text{Substrate Code} \to \text{Generated Artifacts}$$

## 1. Authority Precedence

1. **`PROJECT_INTENT.md`**: Originating purpose, boundaries, and sovereign household constraints.
2. **`AUTHORITY.md`** (this document): Resolves disputes and defines architectural sovereignty.
3. **`docs/`**: Normative design documents, including hardware specifications, appliance storage, and pairing protocols.
4. **`src/jar/`**: Executable code (Python 3.10+ / SQLite3).
5. **Fixtures & Generated Outputs**: Evaluated test outputs, temporary caches, and ephemeral logs.

## 2. Epistemic Integrity

- **Documented $\neq$ Implemented $\neq$ Tested $\neq$ Empirically Validated.**
- Features are marked according to their true implementation state.
- Offline and local capability is primary; cloud capabilities are strictly treated as optional accelerators.
